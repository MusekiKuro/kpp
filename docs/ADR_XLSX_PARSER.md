# ADR: Выбор парсера XLSX для подсистемы импорта

**ID:** ADR-N04
**Дата:** 2026-07-26
**Статус:** Реализовано локально; production approval и staging validation остаются `Confirm first`
**Область:** `nurset-app/lib/import-*`, `app/api/admin/imports/`

---

## 1. Контекст и проблема

Административный интерфейс Nurset поддерживает импорт товаров через **JSON**, **CSV** и локально реализованный серверный **Excel (.xlsx)** workflow. Production-включение XLSX требует staging-проверки и подтверждения владельца.

Загрузка и обработка файлов Excel на стороне сервера Next.js несёт следующие риски безопасности и стабильности:
1. **Безопасность и лицензирование**: Риск использования библиотек с закрытой/двойной коммерческой лицензией или уязвимостями.
2. **Formula Injection & Execution**: Риск исполнения вредоносных формул Excel или передачи команд при экспорте данных.
3. **Decompression Bomb / Denial of Service (OOM)**: Небольшой `.xlsx` (zip-архив) при распаковке XML может израсходовать всю оперативную память сервера.
4. **Внедрение некорректных типов данных**: Необходимость автоматического преобразования дат, вычисляемых значений и объединённых ячеек (merged cells) в канонический формат строк без искажения цен и артикулов (SKU).

## 2. Сравнение кандидатов

| Критерий | `exceljs` (Рекомендуется) | `xlsx` (SheetJS) | `node-xlsx` | `xlsx-populate` |
| --- | --- | --- | --- | --- |
| **Лицензия** | **MIT** | Custom / Dual Commercial (с версии 0.19+) | MIT (зависит от SheetJS) | MIT |
| **Публикация / Реестр** | Официальный npm registry (`exceljs`) | Удалён из npm, распространяется через собственный CDN | npm registry | npm registry |
| **Безопасность & CVE** | Защита от OOM, поддержка streaming | Исторические CVE по Prototype Pollution | Унаследованы от SheetJS | Низкая активность поддержки |
| **Исполнение формул** | **Нет** (извлечение текстов/значений) | **Нет** | **Нет** | **Нет** |
| **Память и стриминг** | Высокая (`exceljs.stream.xlsx.WorkbookReader`) | Высокая | Средняя | Низкая |
| **Поддержка Node.js Server** | Полная (Buffer / Stream) | Полная | Полная | Ограниченная |

## 3. Решение и рекомендация

Рекомендуется использовать пакет **`exceljs`** (версия `^4.4.0`) исключительно на стороне сервера (Node.js Next.js API Routes).

### Причины выбора:
1. **Чистая MIT-лицензия**: Отсутствие коммерческих ограничений и рисков юридического аудита.
2. **Безопасный парсинг формул**: `exceljs` возвращает объект ячейки с вычисленным значением (`cell.result` или `cell.value`), не выполняя код.
3. **Потоковое чтение**: Наличие `stream.xlsx.WorkbookReader` позволяет обрабатывать крупные файлы построчно без загрузки всего документа в RAM.
4. **Поддержка стандартного npm**: Устанавливается из официального реестра `npm` без сторонних CDN.

## 4. Ограничения и Угрозы (Threat Model & Limits)

Для защиты сервера от атак Denial of Service и некорректного импорта вводятся следующие лимиты:

### Жесткие лимиты на обработку XLSX:
- **Максимальный размер файла:** `10 MB` (проверяется до чтения диска/памяти).
- **Максимальное количество листов:** `5 листов` на книгу.
- **Максимальное количество строк:** `5,000 строк` на лист.
- **Максимальное количество колонок:** `50 колонок` на строку.
- **Максимальная длина строки ячейки:** `4,000 символов`.

### Правила обработки данных:
1. **Формулы:** Любое значение ячейки, начинающееся с `=`, `+`, `-`, `@`, экранируется или преобразуется в плоский текст. Исполнение вызовов строго запрещено.
2. **Объединённые ячейки (Merged Cells):** Берется значение только из левой верхней ячейки блока; остальные считаются `null`.
3. **Даты:** Преобразуются в ISO 8601 YYYY-MM-DD.
4. **Цены:** Извлекаются только числовые значения. Текстовые статусы («по запросу») переводятся в `price_mode = 'request'`.

## 5. Человеческий гейт (Human Gate / Confirm First)

Пакет `exceljs` и конвертер уже присутствуют в локальном коде. До production необходимо:

- подтвердить использование зависимости владельцем;
- выполнить staging dry-run и контролируемый `APPLY` на обезличенных данных;
- зафиксировать результаты в release evidence.

Для воспроизводимости локальная установка выглядит так:

```powershell
# Команда установки (только для восстановления зависимостей из lock-файла):
npm.cmd install exceljs
```
